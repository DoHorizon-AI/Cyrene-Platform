# Cyrene-Platform Licensing

This document records the repository's intended license layout and the
architecture that supports it. It is not legal advice and does not replace a
copyright or license review.

## License files

- `LICENSES/AGPL-3.0-only.txt` is the complete GNU Affero General Public
  License, version 3, text used for Platform Core implementation packages.
- `LICENSES/Apache-2.0.txt` is the complete Apache License, version 2.0, text
  used for designated public contracts, protocol inputs, schemas, and SDKs.
- `LICENSE` is a repository-level pointer. Package manifests and this mapping
  identify which license applies to each package.

## Package mapping

### AGPL-3.0-only Platform Core

The following production implementation packages are Core and declare
`AGPL-3.0-only` in their Cargo metadata:

- `cy-adapter-client`
- `cy-execution-control`
- `cy-installation-resolver`
- `cy-kernel-api`
- `cy-kernel-daemon`
- `cy-node-agent`
- `cy-package-runtime`
- `cy-platform-api`
- `cy-resource-manager`
- `cy-runtime-agent`
- `cy-sandbox-client`
- `cyrene-kernel`
- `cyrene-sandboxd`

`cyrene-sandboxd` is a privileged Platform Core service even though it runs
out of process. Its cgroup, device-policy, lifecycle, and cleanup enforcement
are part of the protected implementation boundary.

### Apache-2.0 public interfaces

The following packages declare `Apache-2.0` and are intended to be consumable
outside the monorepo:

- `cy-kernel-contract`
- `cy-proto`
- `cy-manifest`
- `cy-artifact-transfer`
- `cy-execution-fabric`
- `cy-workspace-fabric`

The public adapter SPI is limited to implementation-free facts and the
`HostInventoryProvider` and `ResourceProvider` traits in
`cy-kernel-contract`. Kernel lease, journal, sandbox, runtime, and
orchestration ports remain in Core.

Protocol inputs under `contracts/proto/` and public JSON schemas under
`contracts/schemas/` are Apache-2.0 contract material. The Rust bindings
generated by `cy-proto` are derived from those inputs and are distributed as
part of the Apache-2.0 public crate.

The Python packages `cyrene-artifacts` and `cyrene-preflight` declare the
Apache Software License classifier and Apache-2.0 license metadata.

### Separate decision: official hardware reference implementations

`cyrene-linux-sys-adapter` and `cyrene-nvidia-adapter` are classified as
`SEPARATE_DECISION` in
`tooling/architecture/license-boundaries.toml`. Their current package
metadata is Apache-2.0, but this category keeps the implementation policy
separate from the public contract guarantee. Third parties are not required
to use these reference implementations.

## External extension intent

Third-party plugins, workers, providers, hardware adapters and other
independent extensions that use the designated public Cyrene contracts,
protocols and SDKs may choose their own license, including proprietary
commercial licenses.

This does not change the license applicable to modifications of
Cyrene-Platform Core itself. The statement applies to independently developed
extensions that remain on the documented public process seam; it is not a
blanket exception for anything called a plugin.

Supported extensions must not require linking an AGPL Core implementation
crate. The machine-verifiable boundary is enforced by
`tooling/ci/check-license-boundary.py` and the independent consumer workspace
under `tooling/acceptance/licensing-boundary/`.

## Plugin exception decision

`PLUGIN_EXCEPTION_NOT_ARCHITECTURALLY_REQUIRED` is the current architecture
conclusion. The supported Worker, Provider, Service, and Hardware Adapter
seams use public contracts and versioned gRPC, UDS, or IPC rather than a Rust
link-time plugin ABI. No custom Cyrene legal exception text is created here.

Whether this structure is sufficient for a particular distribution model is a
matter for legal review.

## Source and generated-file policy

- Rust package `license` metadata is the package-level SPDX identifier.
- Protocol and schema inputs carry Apache-2.0 SPDX markers where their format
  supports them; JSON Schema uses a `$comment` marker.
- Generated Rust bindings are not hand-edited and inherit the license policy
  of the public `cy-proto` package and its Apache-2.0 inputs.
- Repository CI and acceptance tooling added for the public boundary is
  Apache-2.0-marked source.
- Existing third-party or vendored material keeps its original notices and
  license. This repository does not relicense dependencies.

## Contributions and future relicensing

The repository currently has contribution guides but no CLA or DCO policy that
grants broad relicensing rights. If DoHorizon later pursues a commercial
dual-licensing or relicensing strategy, maintainers must obtain legal advice
and adopt an explicit contributor policy before relying on that strategy.
This document does not fabricate a CLA, assignment, or relicensing consent.

## Verification

Run the following checks before a public release:

```bash
python tooling/ci/check-license-metadata.py
python tooling/ci/check-license-boundary.py
bash tooling/ci/check-public-packages.sh
bash tooling/acceptance/licensing-boundary/run.sh
```

Public package publication must follow the dependency order in
`docs/release/PUBLIC_PACKAGE_RELEASE_ORDER.md`.
