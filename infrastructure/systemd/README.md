# Native systemd units

Native component units enter through `/usr/bin/cyrene component-run <component-id> -- <startup arguments>`. The host CLI resolves the verified active release and executes that release's manifest-selected binary. Unit arguments remain root-owned service configuration; do not replace the component ID or arguments with environment-controlled executable paths. Workspace Connector and Web BFF use this runner so it can supply the Product contract root pinned by the active release.

The unit files refer to host environment files under `/etc/cyrene`. Operators must provision the required runtime settings, secret files, service accounts, and data directories with deployment-specific ownership and permissions before enabling a unit. Units use the existing `cyrene` and `root` identities. Existing Kernel and adapter peer UID/GID values remain deployment examples and must match the installed service accounts.

If the runtime maintenance broker or its systemd unit is missing on initial install, ordinary apply cannot install it because the broker gate is unavailable. Install the unit through an explicit offline path using a verified artifact. A missing-unit helper may install a unit only after verifying the active release and its unit digest; it must not switch the active release or start the service. The broker remains independent of Kernel restarts and can serve package readiness while Kernel is unavailable.

The root-owned `init-catalog` operation must provision `/var/lib/cyrene/runtime` as `root:cyrene-runtime-maintenance` with mode `2770`. The Kernel accesses this shared journal directory through its `cyrene-runtime-maintenance` supplementary group. Products receive access only to the root-owned `root:cyrene` maintenance UDS socket; do not change the journal directory to group `cyrene` or grant Products directory access.

The Kernel unit deliberately has no `StateDirectory=cyrene`. systemd recursively changes ownership below an existing StateDirectory when its owner or group differs from the unit's configured `User=`/`Group=`. Declaring the `/var/lib/cyrene` ancestor would therefore change the broker-owned runtime journal and private operator-token subtree. The broker's `StateDirectory=cyrene/runtime-maintenance-private` remains scoped to its separate root-only directory.

`cy-runtime-agent` is Worker/container-scoped. Its native-binary catalog entry is not consumed by the active-release host runner: the execution launcher starts it from the pinned Worker OCI image and resolved image digest. There is no production composition-root caller or deployed OCI update API in this checkout. It has no fixed host systemd instance, and the native-binary release does not update the Worker image. Until an updater can enumerate deployed Worker instances and update their OCI image/profile identities, readiness and apply for this component are `UNSUPPORTED` and must remain fail-closed; do not report it as a host-managed service or a completed runtime-agent update.
