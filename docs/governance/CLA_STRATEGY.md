# CLA Strategy | CLA 策略

This is a governance decision record, not a Contributor License Agreement.
It intentionally does not create final legal agreement language.

本文是治理决策记录，不是 Contributor License Agreement（CLA）。本文件有意不
创建具有最终法律效力的协议文本。

## Current state | 当前状态

- No mandatory CLA is present.
- No copyright assignment to DoHorizon is required.
- Contributors retain copyright in their contributions.
- No DCO is currently adopted by this repository.
- Accepted contributions follow the outbound license of their target
  component: `AGPL-3.0-only` for Core and `Apache-2.0` for the public layer.

- 当前没有强制 CLA。
- 不要求向 DoHorizon 转让版权。
- 贡献者保留其贡献的版权。
- 当前仓库没有采用 DCO。
- 被接受的贡献遵循目标组件的对外许可证：Core 使用 `AGPL-3.0-only`，公共层
  使用 `Apache-2.0`。

## DCO and CLA roles | DCO 与 CLA 的作用

| Mechanism | What it can establish | What it does not establish by itself |
| --- | --- | --- |
| DCO | A contributor certification about authorship and the right to submit the change. | Broad commercial relicensing rights. |
| CLA | Additional permissions or grants defined by a reviewed agreement. | Automatic transfer of copyright, unless the agreement explicitly requires assignment. |

If a DCO or CLA is proposed later, it must be introduced as a separately
reviewed repository policy. It must not be inferred from ordinary pull requests
or retroactively applied to historical contributors.

如果未来提出 DCO 或 CLA，应作为单独审核的仓库政策引入。不能从普通 Pull Request
中推定这些权利，也不能追溯适用于历史贡献者。

## Future dual-licensing option | 未来双重许可选项

If commercial, OEM, or enterprise relicensing of Core requires rights beyond
the component's outbound AGPL license, maintainers may evaluate an agreement
that grants additional non-exclusive relicensing rights while the contributor
retains ownership. The final scope and language require legal review.

Before relying on such an option, maintainers must review historical Core
contributions and their actual authorship and license provenance. This record
does not claim that the repository currently has those broad relicensing
rights, and it does not create a plugin exception.

如果 Core 的商业、OEM 或企业再许可需要超出组件 AGPL 对外许可的权利，维护者可以
评估在贡献者保留所有权的前提下授予额外非独占再许可权的协议。最终范围与文本
必须经过法律审核。

在依赖这一选项之前，维护者必须复核历史 Core 贡献及其真实作者身份和许可来源。
本记录不声称仓库当前已经拥有广泛再许可权，也不创建 plugin exception。

# CLA 策略

本文是治理决策记录，不是 Contributor License Agreement（CLA），也不会编写具有最终法律效力的协议文本。

## 当前状态

- 当前没有强制 CLA。
- 不要求向 DoHorizon 转让版权。
- 贡献者保留其贡献的版权。
- 本仓库目前没有采用 DCO。
- 被接受的贡献遵循目标组件的对外许可证：Core 使用 `AGPL-3.0-only`，公共层使用 `Apache-2.0`。

## DCO 和 CLA 的作用

| 机制 | 可以证明的事项 | 本身不能证明的事项 |
|---|---|---|
| DCO | 贡献者对作者身份及提交变更权利的声明 | 广泛的商业再许可权 |
| CLA | 经审核协议所规定的额外许可或授权 | 除非协议明确要求转让，否则不会自动转移版权 |

若未来提出 DCO 或 CLA，必须作为单独审查的仓库政策引入。不得从普通 pull request 中推定，也不得追溯应用于历史贡献者。

## 未来双重许可选项

如果 Core 的商业、OEM 或企业再许可需要超出组件 AGPL 对外许可的权利，维护者可以评估授予额外非独占再许可权、同时让贡献者保留所有权的协议。最终范围和文本须经过法律审核。

在依赖此选项前，维护者必须审核历史 Core 贡献，并核实实际作者身份和许可来源。本记录不声称仓库当前拥有广泛再许可权，也不设置 plugin 例外。
